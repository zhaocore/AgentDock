## 静态发现与设计限制

1. **分类尚未形成不同检索策略。** `internal/query/engine.go` 的分类结果用于 Prompt，所有类型仍调用同一语义召回和图扩展。不能将返回 `global` 当作已完成社区摘要检索。
2. **关键词加权不等于独立关键词召回。** `internal/query/retriever.go` 在向量 top-k 内加分，无法找回被向量阈值排除的精确术语命中。先证明漏召回场景，再增加 PG 关键词通道；不预设引入搜索集群。
3. **输入预算与答案输出上限是不同契约。** 当前 `MaxTokens` 传入生成接口，上下文构建没有预算裁剪；后续还需核对模型适配是否实际透传输出上限。禁止悄悄把既有 `max_tokens` 改成输入预算。
4. **图上下文缺少查询侧证据结构。** 当前 `GraphContext` 只有 Subject/Relations，响应 sources 来自向量 Chunk。图事实进入答案前应找回同租户、有效版本的证据 Chunk，不能只给实体关系字符串编号。
5. **跨库事务不能靠命名保证。** 当前 Publisher 的 Neo4j 操作在单库事务中，PG outbox 完成标记与 job 终态另写；`handlePublish` 清理失败会记录警告后继续成功。需要可恢复协议与故障验收，不能称跨库 ACID。
6. **发布可见性需明确约束。** `documents` 初始状态为 active；向量 SQL 过滤 active，却没有发布任务成功或明确发布版本检查。应以真实集成测试覆盖导入中途查询，确定 PG 与 Neo4j 的共同可见边界。
