# PLAN 261012 — Dashboard 功能迁移（参考 OpenViking web-studio）

对比基准：`/Users/johnson/work/github/OpenViking/web-studio`（下称 web-studio）。
目标：补齐 graphgo dashboard 三个核心缺口，按优先级排序。

## 背景结论

- web-studio 有：文件内容预览（markdown/代码/JSON/YAML/Mermaid + 编辑 + 下载）、树状目录浏览（递归树 + 列式浏览器）、多来源导入（git/web/飞书/ToS）、上传逐文件状态、会话式多轮对话、任务监控、请求日志、用户/权限、i18n。
- graphgo dashboard 现状：21 条后端路由已全部被前端消费；缺口集中在呈现层与数据模型，不是"漏接 API"。
- web-studio **没有**图谱可视化；graphgo 有数据但渲染为表格。

## P1 — 文档内容预览（含后端取原文接口）

- [x] 后端新增 `GET /api/v1/documents/:id/content`：按 RustFS 对象键（租户/KB/文档隔离）流式返回原文（`GetReader`），带租户过滤；不落本地磁盘
- [x] 前端 document-detail 新增"内容"页签：md → react-markdown(GFM)；html/其他 → 纯文本展示（避免渲染任意 HTML）
- [x] 下载按钮（同接口，Content-Disposition: attachment）
- [x] 单测（handler 租户过滤 + 404 用例）+ 覆盖率不回退 + Vitest/Playwright
- [x] Review 补丁（2026-10-14）：inline/下载响应加 `CSP: sandbox` + `nosniff`（阻断上传 HTML 同源 XSS）；改为 `GetReader` 真流式（按元数据大小拒绝超限）；内容页签显示 MIME 与大小

范围控制：编辑保存、Mermaid、代码高亮等 web-studio 高级预览本期不做（YAGNI，md/html 两种格式够用）。
