## 2. 当前事实与影响

### 2.1 当前 Dashboard

`dashboard/package.json` 的名称为 `memgo-dashboard`，使用 Next.js 15、React 19、pnpm；已有基础表格、对话框、主题、双语与测试设施，可以复用。

需要替换的主要业务内容：

- 导航：Requests、Memories、Entities、Categories、Dream、Webhooks、Analytics、Export、API Keys、Users、Configuration。
- `src/utils/api-endpoints.ts` 指向记忆、后台管理和配置接口；不是 GraphGo API。
- `src/lib/auth.tsx` 读取 `access_token`、`refresh_token`，用户类型包含 `name`、`role`。
- `src/middleware.ts` 请求 `/auth/setup-status`，依赖 `memgo_refresh_token`。
- `src/app/api/auth/refresh/route.ts` 调用后端 `/auth/refresh`。
- `src/lib/server-api-url.ts` 的兜底地址为 `localhost:8000`，与 GraphGo 默认 `8080/v1` 不一致。

因此不能只替换 Base URL。认证、路由、类型、请求缓存/轮询、旧页面与测试必须一起调整。

### 2.2 当前 GraphGo

已注册接口包括认证、知识库创建/列表/详情/删除、上传、任务详情/重试、文档删除、问答、实体详情、文档子图与 Embedding 重建请求。

关键契约：

- 登录/注册响应为 `{token, email}`；当前用户为 `{id, email, created_at}`。没有 refresh、setup-status、admin role。
- 知识库分页已有 `data/total/limit/offset/has_more`，可复用分页解析。
- 上传新任务返回 202；同内容 active 文档返回 200 和 `document_id`；进行中重复上传返回 409。
- 任务详情目前仅包含 `id/status/current_step/file_name/error_message`，缺少文档关联、重试上限与时间信息。
- 文档原件保存在 RustFS；PG 有元数据、Chunk 文本及任务记录。
- Query 来源包含文档名、页码、Chunk ID、摘录及版本/召回通道；可从 Chunk 定位文档，不能按文件名猜 ID。
- 实体标识是知识库内的 `canonical_name`，不是全局 UUID；请求必须带知识库 ID。
- 重建记录与暂存已有表和 `rebuild_id`；状态为 `requested/succeeded/failed`，成功切换会清空暂存。
- `internal/modelusage/usage.go` 是单请求用量记录，不是历史 Token 统计系统。
- `/v1/health` 检查 PG/Neo4j，不代表 Redis、RustFS 或模型端点全部健康。

### 2.3 文档漂移

- `AGENTS.md` 仍写无前端、覆盖率 31.0%；需求文档记录 58.0% 和已补测试空洞。实施时先实测覆盖率，再按当前事实同步规则；本次不把历史百分比当实测基线。

## 4. 页面与交互

### 4.1 信息架构

| 路由草案 | 核心内容 |
| --- | --- |
| `/login`、`/register` | 邮箱/密码认证、错误、返回目标页面 |
| `/dashboard/knowledge-bases` | 分页列表、创建、切换、删除确认 |
| `/dashboard/knowledge-bases/[kbId]` | 知识库信息与文档列表、上传入口 |
| `/dashboard/documents/[documentId]` | 元数据、Chunk、关联任务、文档子图 |
| `/dashboard/imports` | 当前租户任务；知识库/状态/文档过滤 |
| `/dashboard/query` | 知识库选择、问题、答案、引用、参数与本次用量 |
| `/dashboard/overview` | 范围内统计与最近任务跳转 |
| `/dashboard/settings` | 当前账号、改密码、主题/语言、健康检查 |

重建操作和状态放在知识库详情，不创建另一套通用任务状态机。旧 MemGo 页面从导航和路由撤下；不保留可触发无效 API 的“锁定功能”。清理仅限本次替换产生的无用文件，先确认用户无独立保留用途。

### 4.2 文档与导入

- 文档列表显示文件名、类型、大小、状态、创建时间和最近任务；默认排除 deleted。
- 文档状态与任务状态分开显示：导入失败不能按文档 `processing` 误判为仍在处理。
- 上传仅允许当前支持格式，每文件上限 100 MiB；批量选择不是新增批量原子上传 API。
- 202 跳转/关联任务；200 定位既有文档；409 显示重复进行中，不自动再上传。
- 轮询任务列表/当前详情，终态停止详情轮询；隐藏页面暂停、切换知识库撤销请求、防止旧响应覆盖新范围。
- 任务仅展示真实 `current_step` 与终态，不把七个阶段等距换算成真实百分比。
- 删除复用已有持久化清理流程；UI 不承诺外部图/原件已同步清完。
- Chunk 按稳定顺序分页展示，不称为完整原文。现有表无原文序号，禁止按 UUID 排序后冒充原文顺序。

### 4.3 问答与图谱

- 必选有效知识库；`top_k` 1–10，`graph_hops` 0–3且初始0；输出预算与检索数量分开。
- 复用同步 `/v1/query`，显示等待和明确错误；首版不加 SSE。
- 来源逐项展示文档名、页码、摘录、Chunk ID、版本、通道；通过 Chunk 详情定位文档。
- 空引用明确为无可引用证据，不补造来源；Token 缺失显示未提供，不写成0。
- 取消浏览器等待不等于撤销已产生的模型费用；不自动重试问答 POST。
- 第一版文档子图采用可点击节点/关系列表；如需交互式画布，单独确认布局库与数据上限。
- canonical_name 使用路径编码，并携带知识库 ID；不同知识库同名实体不能共享缓存。

## 5. API 设计草案

### 5.1 必需新增接口

全部使用现有 JWT 中间件和 tenant；路径按 `/v1` 示例，实际尊重 `SERVER_BASE_PATH`。

| 接口 | 参数/返回要点 | 实现范围 |
| --- | --- | --- |
| `GET /v1/knowledge-bases/:kb_id/documents` | `limit/offset/status/q`；文档摘要、最近任务摘要 | PG 元数据查询；`q` 只检索文件名，不冒充语义搜索 |
| `GET /v1/documents/:document_id` | 文档元数据、Chunk 数、最近任务 | PG；不返回原件对象键、向量、内部载荷 |
| `GET /v1/documents/:document_id/chunks` | `limit/offset`；Chunk 文本、页码、章节、版本、Token 数 | PG；第一版只展示 active 文档 |
| `GET /v1/chunks/:chunk_id` | 完整 Chunk 与所属文档 ID/名称、知识库 ID | PG；问答来源精确跳转 |
| `GET /v1/imports` | `limit/offset/knowledge_base_id/document_id/status`；任务摘要 | PG；全租户列表，过滤器只能进一步收窄 |
| `GET /v1/knowledge-bases/:kb_id/embedding-rebuild` | 当前索引身份及最近代次/目标/状态/错误/已暂存数 | PG；无重建记录时 `rebuild:null` |
| `GET /v1/dashboard/summary` | 可选 `knowledge_base_id`；知识库、非删除文档、active Chunk、任务状态计数、统计时间 | PG 聚合，不调用 LLM，不包含其他租户 |

第一版合计七个新增只读接口，无需为每个页面增加一个聚合接口。

### 5.2 既有接口增量

- `GET /imports/:job_id` 增加 `knowledge_base_id/document_id/retry_count/max_retries/created_at/updated_at/completed_at`；旧字段保留，列表与详情复用同一任务模型。`document_id/completed_at` 按数据库事实可空。
- 知识库详情增加已存索引身份（Provider、模型、维度可空），不返回连接串、密钥或完整服务配置。
- 上传响应保留现有200/202/409与字段；如为关联导航补 `document_id/knowledge_base_id`，只能增量，不能把200去重结果包装成新任务。
- Query 不改生成语义；第一版通过 Chunk 详情定位文档，不强制增加来源字段或修改三套 CLI。
- 删除、重试、图谱与改密码继续用现有入口，不另写 Dashboard 专属业务流程。

### 5.3 参数、分页、错误与可见性

- UUID、状态枚举、文件名查询长度和分页在 HTTP 边界校验。`limit` 1–100、`offset` 非负；非法值400，不截断为合法值。
- 列表复用分页包装；新增响应使用明确类型，空集合为 `[]`；排序使用 `created_at DESC,id DESC` 等稳定组合。
- 文档 `status` 筛选第一版为 `active/processing`；省略返回两者。deleted 不作为可浏览归档；是否做删除历史另确认。
- `q` 使用参数化条件，明确为文件名子串搜索，转义 `%/_`，不让输入暗中改变匹配规则。
- 查文档/任务/Chunk同时验证所属知识库；Chunk/Document/KB租户和知识库字段一致，拒绝不一致记录。
- 知识库不存在或跨租户资源统一404；鉴权401；参数400；既有业务冲突409；基础设施/扫描失败5xx。
- count 与 page 采用一致查询范围和快照策略；逐行扫描及 `rows.Err()` 出错必须失败，不静默返回半页。
- 原件预览不属于 Chunk 浏览；processing/failed 的中间 Chunk 不对浏览接口开放。
- 重建暂存计数按最新 `rebuild_id` 统计；成功后暂存清空，不能报告“0%”。成功显示已完成，失败保留该代次断点；零 Chunk 不做除零计算。
- Summary 不复用可能不同口径的 `document_count` 作为所有上传文档数；各计数明确 active/processing 范围。
- 错误保持兼容 `{error,details?}` 与 `X-Request-ID`；前端保留状态码和请求ID，不把错误对象降成字符串。
- 不把数据库错误、原文、密钥、内部对象键暴露给浏览器；详细结构化诊断写服务端，响应可定位但脱敏。

### 5.4 后端边界与数据变更

- `internal/api` 只解析参数、鉴权上下文、映射HTTP响应；新增读取放 `internal/store/postgres`，模型放 `internal/domain`。
- 导入/删除/重建行为复用 `internal/pipeline`；图读取复用 `internal/query`；Dashboard和Next服务不直连数据库。
- 七个核心读取接口可基于现有表实现，首版不要求新增业务表。
- 现有 Chunk 无持久化位置：首版按 `page_number,created_at,id` 稳定分页，并明确非原文序；若必须精确原文顺序，另立新增 position 字段/写入链路/历史处理方案。
- 仅在查询计划证明需要时新增索引迁移；不提前猜索引，不修改已应用 migrations。
- 历史统计、会话、原文编辑、审核合并、取消导入均不夹带到本次只读补接口中。

## 7. 前端实现边界与认证方案

### 7.1 复用与调整

- 保留 `components/ui`、共享表格/骨架/主题、i18n及测试设施；业务模块按知识库、文档、导入、查询划分。
- 集中API客户端、Zod响应校验、类型与错误；页面只处理展示和交互，不复制状态解释/分页/格式化。
- 利用既有 `use-api-query` 思路，但须补范围变化清理、取消旧请求与防旧响应覆盖；不直接加一个新查询框架。
- 前端状态按用户、知识库、文档ID隔离；退出登录/切换账号清空数据、订阅与轮询。
- 去除旧setup/refresh/admin假设，包名、品牌、favicon、文案改GraphGo；资产来源需明确，不照搬OpenViking品牌。
- 中文/英文、主题和窄屏保持可用；操作使用Lucide图标、标签/tooltip；不嵌套装饰卡片。

### 7.2 已确认认证方案

不为了兼容旧界面给Go服务添加refresh token。

采用Next HttpOnly会话代理：保留Next服务，登录/注册经薄BFF读取GraphGo的 `token` 并写HttpOnly会话Cookie；业务请求由限定GraphGo地址/路径的同源代理注入Bearer，Go鉴权与CLI契约不变。Cookie有效期不超过JWT `exp`，过期401清理并重新登录。

约束：SameSite、Secure、Origin/CSRF校验；代理不能接收任意外部URL或客户端tenant；转发保留状态码、Request-ID、取消和上传边界；100 MiB上传不能落Next临时磁盘，也不能被默认代理限制截断。退出只清浏览器会话，不宣称吊销已签发JWT。

不建设浏览器sessionStorage/localStorage Bearer直连方案。删除旧refresh handler，新增登录/注册/退出/session与限定代理边界，并补认证/代理测试。
