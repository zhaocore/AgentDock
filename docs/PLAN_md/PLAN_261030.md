### 目标链路与职责

```text
每天 09:00（Asia/Shanghai）／用户手动执行
  → 校验任务 owner、Agent 与登录配置权限
  → 原子领取本轮运行、冻结本轮配置、写入 Asynq
  → Worker 并发采集明确 URL
  → Agent 逐页提炼
  → Agent 汇总 Markdown
  → RustFS 保存报告
  → MySQL 发布成功记录
  → dashboard 查看／下载
```

| 路径 | 实施责任 |
| --- | --- |
| `internal/domain` | 任务、运行、逐页结果与阶段模型 |
| `internal/config` | 域名范围、登录配置、采集与 Agent 资源上限 |
| `internal/store/mysql` | 用户隔离、运行领取、幂等、进度和报告发布元数据 |
| `internal/worker` | 定时入队、抓取、重试、流水线编排 |
| `internal/agent` | 后台报告执行接缝、正文提炼与汇总 |
| `internal/store/rustfs` | 复用对象存取，保存正文、中间产物与报告 |
| `internal/api` | HTTP 参数、鉴权、任务与报告接口 |
| `agents/skills/url-to-markdown` | 复用转换函数，补充浏览器无磁盘采集入口 |
| `dashboard/src/features/dutybot` | 任务表单、进度、报告展示与下载 |
| `cmd/server/main.go` | 依赖装配、调度启动与关闭 |

### 第四阶段：调度、执行与故障收敛

- [x] 使用既有 Asynq 的固定每日派发器，显式使用 Asia/Shanghai，触发时读取启用任务；配置变化即时影响下一次派发，不维护逐任务注册项。服务关闭时停止新增入队并收敛在途任务。
- [x] 分开调度派发与运行执行：固定派发任务不携带配置，读取启用任务后按 owner、任务 ID 与计划日期领取运行，执行任务仅携带用户 ID 与运行 ID；均不携带 Cookie 或正文。不修改既有 repo 与 Confluence 载荷，Worker 只执行与持久化记录匹配的任务。
- [x] 明确 MySQL 领取与 Redis 入队之间的故障处理：入队失败记录错误并释放占用，进程在两步之间中断时通过持久化派发状态收敛，不能留下永久占用的 queued 记录。
- [x] 打通 `queued → running → succeeded/failed`，运行阶段区分采集、报告和发布，报告阶段包含逐页提炼与分层汇总；逐页记录进度及脱敏错误。Asynq 重投不得重复执行已终结轮次。
- [x] 同一任务重叠触发不启动新流水线；定时跳过留记录，手动重复执行返回明确冲突。失败后手动执行创建新轮次，不伪装为断点继续。
- [x] 统一管理请求级重试与 Asynq 重投，避免嵌套重试导致超过约定尝试次数；任一页面最终失败取消本轮剩余工作，不发布完整报告。
- [x] 重启时将中断运行收敛为失败，阻止旧消息重新发布；重启前 queued 轮次也置失败，由用户明确手动建立新轮次。只注册未来定时，不补跑停机错过的时刻。

验收：验证手动与定时竞争、重复投递、Worker 崩溃、队列错误、重启、任务停用和错过时刻；使用 Redis/Asynq 的真实集成覆盖，不能仅以时间函数单测作为调度验收。
